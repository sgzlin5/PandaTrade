# PositionTrader

> 源文件：`EA/PositionTrader.mq5` ｜ 详细口径与参数（自 README 拆分） ｜ [返回 README](../../README.md)


> `EA/PositionTrader.mq5`

把 `PositionTool` 画出来的仓位工具**真正挂成挂单**（Buy / Sell Limit 或 Stop）。

#### 为什么必须是独立的 EA

**MQL5 的指标不能下单** —— `OrderSend` / `CTrade` 在指标里不可用。所以"画"留在指标里，
"发单"只能另起一个 EA。两者靠**一个图表对象**通讯：指标每次重画把**当前选中工具**的挂单意图写进去，
EA 点击时读它 → 校验 → 发单。

#### 接口契约（改一端必须同步改另一端）

| 项 | 值 |
|---|---|
| 对象名 | `PT_ORD` |
| 存放位置 | 该对象的 `OBJPROP_TOOLTIP`（**不是** `TEXT`） |
| 载荷 | `TVPT1\|NONE` 或 `TVPT1\|<L或S>\|<entry>\|<sl>\|<tp>\|<lots>\|<R>\|<noTrade>\|<id>` |

> **为什么用 TOOLTIP 而不是 TEXT**：这样这个对象可以是一个**空文字标签** —— 视觉上完全不存在，
> 连"藏对象藏出可见垃圾"的风险都没有（本指标已经在 `OBJPROP_HIDDEN` 上吃过一次亏，见上文坑 ④）。
> **为什么不让 EA 自己读那三根线**：几何确实读得到，但**手数读不到** —— 它是 R / 风险% / 最小手数
> 一起算出来的**结论**。让 EA 再算一遍，就等于把同一套定仓公式维护两份，"两个真相源"迟早对不上。

#### 操作

| 动作 | 结果 |
|---|---|
| `按工具挂单` | **指标模式**。第一次点只是**上膛**；`6 秒`内再点一次 `确认挂单?` 才真发单 |
| `BUY` / `SELL` | **手动模式**（图上没有指标时出现）。市价进场，手数 / 止损 / 止盈来自 `InpManual*`；同样两步确认 |
| `平掉本EA仓` | 平掉本 EA 在本品种上的全部持仓。**一次点击直接执行** |
| `撤销挂单` | 撤掉**本 EA 的 Magic + 本品种**的全部挂单（已成持仓的不动）。**一次点击直接执行** |

> **为什么"平仓/撤单"不二次确认，而"开仓"要**：平仓和撤单是**降风险**，
> "急着平却要点两下"本身就是风险；开仓是加风险，误点一次就出去一张真单。
> 一视同仁地都加两步，等于在错的地方设了摩擦。

挂单类型由入场线相对市价的位置自动决定：入场在更有利的一侧 → `Buy/Sell Limit`；
越过市价 → `Buy/Sell Stop`。按钮 tooltip **每秒刷新**，悬停就能看到"现在这一下会挂出什么单"。

> ⚠️ **左下角提示会被时间轴盖住**：MT5 的**时间轴（日期刻度）就画在图表底边**，
> 第一版把两条提示贴在距底边 `12px` / `30px` —— 下面那条基本整条压进时间轴里，上面那条也吃掉半截。
> 现在默认 `46px`（副标题）/ `66px`（正文），并做成输入 `InpMsgBottomPx` 可调：
> **不同终端的图表字号不同，时间轴高度跟着变，写死一个数迟早不对**。

#### 两种模式（按图上有无指标**自动**切换）

| | 指标模式 | 手动模式 |
|---|---|---|
| 触发条件 | 图上存在接口对象 `PT_ORD` | 不存在（没挂指标 / 旧版指标 / **策略测试器里**） |
| 按钮 | `按工具挂单` `撤销挂单` | `BUY` `SELL` `平掉本EA仓` `撤销挂单` |
| 下单 | 按工具的入场 / 止损 / 止盈挂 Limit / Stop | **市价**进场，参数来自 `InpManual*` |
| 手数 | 指标算的（含面板上手填的） | `InpManualLots` |

切换由 `OnTimer` 每秒检测，**不需要重挂 EA** —— 你在图上挂上 / 卸载指标，按钮组会自己换，
并打一行 `[模式] 切到…`。

> ⚠️ **手动模式只做市价单**：没有指标就没有"入场线"，也就没有可挂的价位。
> 这不是偷懒，是**信息不存在** —— 编一个价位出来才是错的。
> ⚠️ 模式切换**一定显式可见**（按钮文字、颜色、日志全变），绝不静默：
> 否则你以为在按工具挂单，实际下出去的是一张市价单。

#### 在策略测试器里当手动回测面板

这就是做这一步的目的（对照 [`Manual-backtesting-MT5`](https://github.com/TeknoTrader/Manual-backtesting-MT5) 那套做法）：

1. `Ctrl+R` → 策略测试器 → **专家顾问**选 `PositionTrader` → 选品种 / 周期 / 日期 → 勾**可视化**；
2. 模型建议 `每一分钟OHLC`（快）或 `基于真实报价的每一跳`（准，慢）；
3. 跑起来后图上**没有指标** ⇒ 自动进手动模式 ⇒ `BUY` / `SELL` 进场、`平掉本EA仓` 出场；
4. 跑完看**测试器自己的报告**（胜率、盈亏比、最大回撤、Sharpe…）。

> 统计是**测试器**给的，不是 EA 给的 —— 因为那些单是在测试器的模拟账户上成交的。
> ⚠️ 手数 / 止损 / 止盈在**测试器的输入标签页**里改，**一次运行中途改不了**（想中途改要另加控件）。
> ⚠️ 我没验证过"指标的图表对象在测试器里渲不渲染、能不能点/拖"——那是另一条路（B），没做。

#### 把指标和 EA 一起放进策略测试器（实验性）

**机制**：策略测试器**本身不跑指标**，唯一途径是让 EA 用 `iCustom()` 创建它；
而且测试器**默认把 `iCustom` 创建的指标藏起来**，必须调 `TesterHideIndicators(false)`。
本 EA 已内置这条路，开关是 `InpTesterSpawnIndicator`（**只在测试器里生效** ——
实盘图上你已经有指标了，再拉一个会出现两套面板）。

**步骤**：`Ctrl+R` → 专家顾问选本 EA → 勾**可视化** → 输入标签页把 `InpTesterSpawnIndicator` 设 `true`
（建议同时开 `InpDebug`）→ 开始测试。

**然后看日志，这几行就能定性：**

| 日志行 | 它证明什么 |
|---|---|
| `[测试器] 拉起指标 … handle=N err=0` | `iCustom` 本身成没成（`err≠0` 就是没成） |
| `[测试器] 指标自检：面板对象=在/缺失 接口对象=在/缺失` | 指标有没有真的跑起来、有没有建出对象 |
| `hook OnCalculate 首次被调用` / `hook OnTimer 首次被调用` | **指标**在测试器里能用哪个轮询节拍（可能都不行） |
| `DBG … poll-click <…>` | 按钮按下被轮询接住了（说明 STATE 语义在测试器里成立） |
| `DBG … object-click <…>`（需 `InpDebug`） | 点击事件到底送没送到 |

> ✅ **已实测确认（用户报告）**：测试器里指标**按钮点击无效** —— 即 `CHARTEVENT_OBJECT_CLICK`
> 确实不送给指标。这不是本指标的 bug，是测试器的已知限制。
> 对策：指标侧也加了**轮询兜底**（`PollOwnButtons()`，读 `OBJPROP_STATE`），
> 与 EA 侧同一套做法 + 同一个 `GetTickCount()` 500ms 去重。
> ⚠️ 但轮询需要一个"节拍"，而**测试器里指标能不能用 `OnTimer` / `OnCalculate` 我并不知道** ——
> 所以两个钩子都装了，并各打一行首次调用日志，让结果自证。
> **判定**：若两行 `hook …` 都没出现 ⇒ 指标在测试器里既收不到事件也没有节拍，
> **这条路到此为止**，交易只能用 EA 自己的按钮（那条走 `OnTick` 轮询，是通的）。
>
> ⚠️ **即使按钮通了，拖线仍然不能用** —— 测试器是回放，没有"拖"的时机。
> 所以测试器里的可用动作是：`+做多/做空`（以当前价 + 1.5×ATR 生成工具）
> → EA `按工具挂单`（入场就在市价附近，需开 `InpAllowMarket` 才挂得出去）
> → `平掉本EA仓`。**入场价/止损宽度在测试器里改不了**，这是拖拽缺失的直接后果。
> ⚠️ 手数输入框在测试器里多半也用不了（编辑完成事件），但 `-` / `+` 两个按钮是按钮，走轮询。
>
> ⚠️ **必须说清的一件事（这里曾经写错过）**：**"按钮在可视化测试器里点不动"是 MQL5 社区的已知老问题** ——
> [1](https://www.mql5.com/ru/forum/510179) · [2](https://www.mql5.com/en/forum/444528) ·
> [3](https://www.mql5.com/en/forum/223894) · [4](https://www.mql5.com/en/forum/311922)。
> 本仓库曾据"有人做出了这类工具"就断言"点击事件在测试器里可用，已有独立证据"——**那是过度推断，已收回**：
> 项目的存在只说明有人做成了，不说明机制在你这台终端上也成立。

#### 拒单条件（每条都给具体原因，绝不猜着往下走）

- 指标没挂 / 指标在跑但**没有挂单接口的旧版本**（这两种给**不同**的提示，不混为一谈 ——
  曾经的措辞一律说"没挂指标"，把一次真实的排查指向了错误方向）/ 没选中工具 / 意图格式不认识
- 缺止损或止盈线；止损止盈方向与多空矛盾；离入场小于券商最小距离
- 入场距市价小于 `SYMBOL_TRADE_STOPS_LEVEL`（可开 `InpAllowMarket` 改走市价）
- 指标判定「不建议开仓」（最小手数下已超 R）—— 直接把指标的风控结论挡在发单之前
- 终端 / EA / 账户未允许交易；品种禁止交易或只允许单边
- 手数按品种步长归一后与指标算出的不一致 → **照挂，但在日志与提示里写明差在哪**
- 手动模式下：止损 / 止盈点数小于券商要求的最小停价距离 → 提示**把哪个输入调大**，不静默改

#### 输入参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `InpMagic` | `20260928` | 本 EA 的 Magic；撤单 / 平仓只碰自己的单 |
| `InpSlippagePts` | `30` | 允许滑点（点，仅市价单用） |
| `InpAllowMarket` | `false` | 指标模式下入场价离市价太近时，允许改成市价单进场 |
| `InpManualLots` | `0.10` | **手动模式**手数 |
| `InpManualSLPoints` | `200` | **手动模式**止损（最小变动 `SYMBOL_POINT` 的个数；`0` = 不设） |
| `InpManualTPPoints` | `400` | **手动模式**止盈（同上；`0` = 不设） |
| `InpColorBuy` / `InpColorWarn` | 涨绿 / 信号橙 | 成功 / 提示色 |
| `InpFontSize` | `10` | 左下角提示字号 |
| `InpMsgBottomPx` | `46` | 提示距**图表底边**的像素（正文再 +20）。⚠️ MT5 的时间轴就画在底边，被遮住就调大 |
| `InpTesterSpawnIndicator` | `false` | 测试器里由 EA 用 `iCustom` 拉起 `PositionTool`（**仅测试器生效**） |
| `InpDebug` | `false` | 专家日志：每次意图解析一行 |

#### 验收

- EA 启动日志：`TradFi_PositionTrader build=v1.11-s1 已启动 | XAUUSD.ct … | Magic=… | 模式=… | 接口对象 PT_ORD`
  —— `模式=` 直接告诉你它现在跑的是指标模式还是手动模式
- 点 `按工具挂单` → 左下角出现「已上膛」，按钮变 `确认挂单?`；**6 秒不点会自动解除**
  （避免"手滑上膛、半小时后误点发单"）
- 成功日志带**精确占用保证金**：`… | 占用保证金=1760.00`（`OrderCalcMargin` 在 EA 里可用，
  正好补上指标端 `marginProbe=FAIL` 的那个缺口）
- 把指标卸掉 → 一秒内按钮组应换成 `BUY` / `SELL` / `平掉本EA仓`，并打出 `[模式] 切到手动模式`
- ⚠️ **EA 换版本必须重新挂载**：MT5 **不会**热重载正在跑的 EA
  （本仓库有日志为证：重新编译过三次，日志里始终只有最早那一次启动行）
