# 事件基线归档（`docs/baselines/`）

这里存放 `Structure` 导出的**事件 CSV 快照**，用于"改前导出一份 → 改代码 → 再导出一份
→ 逐行 diff"的归因流程（见 `docs/plans/2026-09-23-TTrades-alignment.md` 阶段 0）。

导出方式：在 MT5 里勾上 `InpDumpEvents`，每次全量重算会**覆盖**写
`MQL5\Files\Structure_events_<品种>_<周期>.csv`。

---

## ⚠️ 先读这一条：文件名里带 `BUGGY` 的两份，**部分可用**

| 文件 | 什么坏了 | 什么还能用 |
|---|---|---|
| `2026-09-24-v1.50-s18-BUGGY-closure-accumulation_XAUUSD-M5.csv` | `CLOSURE` 行 | **其余全部行仍然有效** |
| `2026-09-24-v1.50-s18-BUGGY-closure-accumulation-t2_XAUUSD-M5.csv` | `CLOSURE` 行 | **其余全部行仍然有效** |

**坏在哪**（详见 plan §35.2 / §37.2）：`v1.50-s18` 的 `ComputeClosures()` 漏了自复位，
`g_result.nClosure` 跨全量帧**累加**。三点实测序列：

| 时刻 | `rates` | `nodes` | `closure` |
|---|---|---|---|
| 13:55:45 | 100152 | 59 | 59（首帧，日志逐条可数） |
| 13:57:35 | 100153 | 58 | 117 |
| 14:02:35 | 100154 | 58 | 175 |

每来一根 M5 净增"当帧节点数"（58）——所以这两份里的 `CLOSURE` 行**是跨帧叠加的重复内容**，
且 bar 下标会随新 K 线整体 +1，**无法靠"锚点是否重复"筛掉**（plan §35.4 记录了两种失败的筛法）。

**为什么其余行仍可用**：被累加的只有 `nClosure` 一个计数；
`MSS` / `BOS` / `CISD` / `SWEEP` / `FVG` / `OB` 的计数都在各自的复位点正常清零
（`docs/baselines` 之外还有一层佐证：同一文件的头部 `nodes=58 mss=6 bos=9 cisd=23` 三个计数常年稳定）。
所以做 **"既有事件集合是否逐字不变"** 这类对照时，**按类型过滤掉 `CLOSURE` 行即可**。

> 一般用法（PowerShell）：
> ```powershell
> $rows = Get-Content <baseline>.csv -Encoding UTF8 |
>         Where-Object { $_ -notmatch '^#' -and $_ -notmatch '^seq,' -and ($_ -split ',')[1] -ne 'CLOSURE' }
> ```
> ⚠️ 这些文件是 **UTF-8 无 BOM**，`Get-Content` 必须带 `-Encoding UTF8`，
> 否则 PowerShell 5.1 按 ANSI 读会把中文表头读成乱码（硬约定 6）。

**不要**把带 `BUGGY` 的文件当成"某个版本的正确基线"来归档比较 ——
它们在 bug 修复（`v1.50-s19b`）之后**不再代表任何版本的真实输出**。

## 命名约定

```
<日期>-<构建指纹>[<修饰>]_<品种>-<周期>.csv
```

- `<构建指纹>` 取自 CSV 头部的 `build=`（即 `BUILD_TAG`）—— **判断"这份文件来自哪一版"的唯一可靠依据**。
  不要靠文件时间戳推断：`.ex5` 的哈希在两次同源编译之间都会变（plan §32.3）。
- `<修饰>` 只用于标注**数据本身有问题**的归档，目前只有 `BUGGY-closure-accumulation`。
