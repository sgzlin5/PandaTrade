# PositionTool

> 源文件：`Indictor/PositionTool.mq5` ｜ 详细口径与参数（自 README 拆分） ｜ [返回 README](../../README.md)


> `Indictor/PositionTool.mq5`

对齐 TradingView 的 **Long / Short Position** 工具：在图上摆入场 / 止损 / 止盈三根线，**盈利区绿、亏损区红**，实时给出点数、价格 %、账户货币金额、盈亏比，以及按风险 % 反推的建议手数。

#### 为什么要有这个文件

MT5 原生只有"**开仓之后**的止损止盈虚线"，没有**下单之前**的量算工具。这个指标补的就是那段空白：把"这笔我愿意亏多少、能赚多少、该下几手"一次性摆在图上。

#### 四个必须绕过的技术坑（决定了它的画法）

1. **图表对象没有 alpha 通道** —— 做不出 TradingView 那种半透明色块。→ 矩形用 `OBJPROP_FILL` + `OBJPROP_BACK`（画在 K 线之下），颜色按 `InpZoneMix` 与**图表底色混色**，得到视觉上接近半透明的暗色。
   ⚠️ 代价要写明：它是**不透明填充 + 退到背景层**，不是真透明。想要真透明只能换成 `OBJ_BITMAP_LABEL` + 带 alpha 的 PNG，那会牺牲"跟着价格/时间走"的能力。故此处选前者，并保留 `InpFillZones=false` 的纯线框模式。
   **浓淡就一个旋钮**：`InpZoneMix`（默认 `25`）—— `15` 基本只剩一层底色，`40+` 接近饱和纯色。
   > 改这个输入**不需要重新挂载**：MT5 会以 `REASON_PARAMETERS` 重初始化，`Rebuild` 从既有对象恢复
   > 工具，画的东西不会丢。但**改代码里的默认值对已挂载的实例无效**（输入是随实例保存的）。
2. **拖拽事件（`CHARTEVENT_OBJECT_DRAG`）只在鼠标松开后报一次**，且 `OBJ_TREND` 拖中点与拖端点都只给出一份新几何。→ 统一以 `modifier 0` 的 time / price 为真值来源，拖完立刻把另一端归一化（水平线强制 `price0 == price1`），线不会被拖斜。
   ⚠️ 另外**绝不重置 `OBJPROP_SELECTED`**：MT5 必须先选中对象才能拖动，每次重画都清选中会让线变得"拖不动"。
3. **换周期 / 改参数会 `OnDeinit + OnInit`，但图表对象还在**。→ `OnInit` 不做"清空重画"，而是从既有对象的**名字**里 `Rebuild` 出状态（命名 `PT_<id><L|S>_<part>`），否则每次切周期用户的仓位工具都会消失。
4. **抓手不能画在别的线的端点上**（`v1.12-s1`）。时间宽度抓手原本是画在**入场线两个端点**上的 8px 圆点（`OBJ_ARROW 159`），坐标与 `OBJ_TREND` 的端点**完全重合** → MT5 把鼠标命中判给了**线**：用户拖到的是入场线，工具被整体平移，**宽度纹丝不动**。
   → 抓手移到**工具外侧**（离三根线都有距离），并换成 `OBJ_TEXT` 字形（命中框 = 文字外框，比圆点大得多、字号可调）；另外在面板上补一组 `宽度 −N / +N` 按钮兜底。

#### 一处与原工具的**有意偏离**

TradingView 的绿 / 红是按**角色**固定的（目标=绿、止损=红）；本指标按**结果**着色 —— 把止盈拖到入场另一侧时，那块区域其实是亏损，就显示红色并给出负数。即 **亏损必红、盈利必绿**，不被角色骗。

#### 操作

| 动作 | 结果 |
|---|---|
| `+ 做多` / `+ 做空` | 以当前 Ask / Bid 新建工具；止损 = `InpDefaultStopPips`（默认 `1.5 × ATR14`），止盈 = 止损 × `InpDefaultRR` |
| 拖**入场线** | 整个工具平移（止损止盈一起走） |
| 拖**止损线** / **止盈线** | 只动那一根 |
| 拖工具**外侧的 ◆ 抓手**（左右各一个） | 调整工具的时间宽度（`v1.12-s1`：抓手已挪到三根线**之外**，见下文"抓手抢不到鼠标"一节） |
| 面板「**宽度 −N / +N**」按钮 | 同上，**不依赖鼠标命中**的兜底通道（`InpWidthStepBars` 控制每次几根） |
| 点**任意一根线** | 选中该工具（面板切换显示它的数字） |
| `Delete` 键 / `删除选中` | 删除选中的工具 |
| `清空全部` | 删掉图上所有工具（最多同时 32 个） |
| `收起面板` / `展开面板` | 折叠左上角说明区，**只留操作按钮**（画线与工具完全不受影响）。位置刻意不动，免得肌肉记忆失效 |
| 手数行右侧的 `-` `值` `+` | **手动手数**：直接输入后回车即改为手动；`-`/`+` 按品种步长增减；**填 `0` 或清空 = 回到自动**。手动值优先于一切自动口径，且不参与「不建议开仓」判断 |

> **想真正把工具挂成单**：本指标**不能下单**（MQL5 硬限制：`OrderSend` 在指标里不可用）。
> 必须把 `EA/PositionTrader.mq5` 也挂到**同一张图**上 —— 它会读走本指标发布的挂单意图，
> 并在按钮行右端给出【按工具挂单】/【撤销挂单】。详见「EA 列表 → TradFi_PositionTrader」。

> **折叠状态存在哪**：就存在折叠按钮**自己的文字**里（`收起面板` / `展开面板`）。
> 换周期 / 改参数 / 重编译时图表对象都还在，`LoadUiState()` 读回按钮文字即可恢复 ——
> 于是不需要第二个存储位，也就**不存在"两个存储位不一致"这一类 bug**。
> 这与本指标"状态都从既有对象里 `Rebuild`"是同一套做法（见上文坑 ③）。
> ⚠️ 收起后**手数 / 成本 / 盈亏比只存在于面板里**，收起即看不见（按钮 tooltip 有提示）；
> 区标签上的点数与金额不受影响。

#### 定仓三档（默认：以损定仓）

| 模式 | R 来自 | 手数 |
|---|---|---|
| `LOT_FIXED_R` **（默认）** | **固定金额** `InpRiskMoney` | `R / (止损距离 × 每手每价格单位金额)` |
| `LOT_RISK_PERCENT` | 账户规模 × `InpRiskPercent` | 同上，R 随账户浮动 |
| `LOT_FIXED` | — | 直接用 `InpFixedLot`，风险由几何决定 |

用法就是**拖止损线**：止损拖远 → 手数自动变小，被打到就是亏掉 R。
面板把算式摊开，便于手算复核：

```
手数  0.40（以损定仓  R = 100.00 USD）
算式  R 100.00 / (止损 250.0 点 x 1.00 USD/点/手) = 0.40 手
成本  ≈1760.00 USD 保证金（估算）
```

> **为什么默认是固定 R 而不是按 %**：R 用**金额**表达时与账户规模**解耦**，
> "这一笔亏 1R"在复盘里才是可比的量；按 % 定仓则账户一变，同一个 1R 的含金量就跟着变。
> 想换回按 %：把 `InpLotMode` 改成 `LOT_RISK_PERCENT`。
> ⚠️ **已挂在图上的实例要手动改**——默认值只影响新挂载。

**成本（开仓占用保证金）**：优先 `OrderCalcMargin`（走经纪商自己的公式）；
取不到时退到 ① `SYMBOL_MARGIN_INITIAL × 手数`（仅当保证金货币 = 账户货币）
② `名义价值 / 杠杆`，并在数字前加 **≈** 标为估算。

> ✅ **已实测定案（本终端 XAUUSD.ct）**：启动日志连续三次报 `marginProbe=FAIL 0.00 (lot=0.01)` ——
> **`OrderCalcMargin` 在指标里根本调不通**（它是交易类函数，只对 EA / 脚本开放）。
> 故指标面板上的"成本"**永远是估算值（带 ≈）**，这是 MT5 的硬限制，不是实现缺陷。
> **想要精确口径**：`PositionTrader`（EA）下单成功后的日志里有 `占用保证金=…`，
> 那一份才是 `OrderCalcMargin` 算的精确值 —— 这也是那个 EA 存在的意义之一。

**手数撑不住最小手数时 ⇒ 直接判「不建议开仓」**

MT5 的品种有最小手数（多数是 `0.01`）。当 `R / (止损距离 × 每手每价格单位金额)` **小于最小手数**时，
用最小手数下单**必然超过设定的 R** —— 此时面板**不再给出被顶上去的那个手数**
（`0.01` 摆在那里会被当成"可以下"），而是直接判不建议开仓：

```
手数  --（⚠ 不建议开仓）
⚠ 最小手数 0.01 下亏损 143.00 USD（> 设定 R 100.00 USD）
  止损收到 ≤ 8741.3 点（现 12500.0 点），或 R 提到 ≥ 143.00 USD
```

同一句提示也会**直接写在亏损区上**，不只藏在面板里。两条出路都给了确切数字：
止损收到 `≤ R / (最小手数 × 每点每手价值)` 点以内，或把 R 提到"最小手数下的实际亏损额"。

> 判据是**严格**的：只要算出的手数 `< 最小手数` 就判不建议（哪怕只超 1%）。
> 这符合本指标一贯的取舍 —— 宁可把数字讲清楚，也不做"差不多就行"的静默放宽。
> 固定手数模式不参与这个判断（那是你显式指定的手数），但若 `InpFixedLot` 低于最小手数，会单独提示已取最小手数。

**手动手数（覆盖上面三档）**：「手数」那一行的右边有 `-` `[值]` `+` 一组控件。
直接输入后**回车**即改为手动；`-`/`+` 按品种步长增减；**填 `0` 或清空 = 回到自动**。
手动值**优先于一切自动口径**，且**不参与「不建议开仓」判断**（那是显式指定，不是"算出来不够"）；
但被最小手数 / 步长归一过会明确写出来 —— 归一后的实际风险与你的预期不同，不能默默吞掉。

> 它存在一个**空文字标签**（`PT_Prefs`）的 TOOLTIP 里，所以换周期 / 改参数 / 重编译都还在。
> ⚠️ 这个对象**刻意不在 `OBJ_PREFIX` 之下** —— 否则点一次「清空全部」就把你的偏好一起清掉了；
> 代价是 `OnDeinit` 必须**单独**删它，否则会漏在图上（代码里已这么处理）。
> 用 `OBJ_EDIT`（MT5 里唯一能"直接在图上敲数"的对象）是靠**编译探针**先确认了
> `CHARTEVENT_OBJECT_ENDEDIT` / `OBJPROP_READONLY` / `OBJPROP_ALIGN` 在本版存在才写的 ——
> 顺带确认了**不需要**任何 `ChartSetInteger` 开关，编辑完成事件是自动发的。

#### 输入参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `InpLotMode` | `LOT_FIXED_R` | 三档定仓：以损定仓（固定 R）/ 按账户风险 % / 固定手数 |
| `InpRiskMoney` | `100.0` | **以损定仓的 R**（账户货币固定金额） |
| `InpRiskPercent` | `1.0` | 单笔风险占账户 %（`LOT_RISK_PERCENT` 用） |
| `InpFixedLot` | `0.10` | 固定手数（`LOT_FIXED` 用） |
| `InpAccountSize` | `0.0` | 账户规模，`0` = 用账户余额 |
| `InpDefaultStopPips` | `0.0` | 新建工具的默认止损距离（点），`0` = `1.5 × ATR14` |
| `InpDefaultRR` | `2.0` | 默认盈亏比 |
| `InpPipSize` | `0.0` | 1 点的价格，`0` = 自动（3 / 5 位小数按 **10 个最小变动 = 1 点**） |
| `InpColorProfit` / `InpColorLoss` | 涨绿 / 跌红 | 盈利 / 亏损色（TradFi 色板） |
| `InpColorEntry` | 主蓝 | 入场线色 |
| `InpColorHandle` | `clrWhite` | **时间宽度抓手色**（`v1.12-s1`；抓手画在工具外侧，要显眼） |
| `InpWidthStepBars` | `5` | 面板「宽度 −N / +N」按钮每次增减的 **K 线根数** |
| `InpColorWarn` | 信号橙 | 警示色（用于「不建议开仓」等提示） |
| `InpFillZones` / `InpZoneMix` | `true` / `25` | 是否填充盈亏区、**色块浓淡 %**（与图表底色混色；越小越淡，`0` = 纯底色，`100` = 饱和纯色） |
| `InpFontSize` | `9` | 字号 |
| `InpPanelBg` | 深背景 | 面板底色 |
| `InpShowPanel` | `true` | 信息面板总开关（`false` = 永不显示，也一并清掉折叠按钮）；日常收纳请用界面上的**收起面板**按钮 |
| `InpKeepOnRemove` | `false` | 卸载指标时保留画图（重新挂载后 `Rebuild` 恢复） |
| `InpDebug` | `false` | 专家日志：每个事件一行 `DBG` |

#### 验收

- 挂上后日志应有一行 `DBG v1.10-s1 init <symbol> <TF> tools=0 pip=… mpp=… | marginProbe=…`。
  两个字段决定一切：`mpp` = **每手、每 1 个价格单位的账户货币金额**（金额 / 手数 / 成本三栏是否可信），
  `marginProbe=OK/FAIL` = **`OrderCalcMargin` 在本指标里能不能调**（成本一栏是精确值还是估算值）
- 点 `+ 做多`：应立刻出现蓝色入场线、红色止损区、绿色止盈区，面板给出点数 / 金额 / 盈亏比 / 手数 /
  算式 / 保证金占用
- **`mpp=0.00000`** ⇒ 该品种的 tick 数据没就绪，此时"金额"不可信。指标会退到**合约面值**兜底
  （仅当盈利货币 = 账户货币，如 XAUUSD：100oz ⇒ 1.00 价格 = 100 USD/手，日志里应看到 `mpp≈100`）；
  若两者货币不同（如欧元账户做黄金），**不猜汇率**，面板仍显示 `--`
- **拖动止损线时手数应随之变化**（以损定仓的核心行为）：止损拖远 → 手数变小，`-R` 金额保持不变
- **时间宽度可调**（`v1.12-s1`）：拖工具**外侧的 ◆**，或点面板「宽度 −5 / +5」。两种入口都改了同一个 `t2`，
  面板的「宽度 N 根」应立刻跟着变；日志会打一行 `DBG … object-drag <PT_1L_HL>`（拖抓手时）
- **手数旁出现红字提示** ⇒ 算出的手数低于该品种最小手数，已取最小手数，
  提示会直接报出**实际 R**（此时实际风险**大于**设定的 R）

#### 已踩过的坑：工具"加出来却拖不动"（已修复）

**根因：`OBJPROP_HIDDEN=true` 会让对象对鼠标完全不可见。**

第一版给所有对象都设了它（本意只是不想污染 `Ctrl+B` 对象列表），结果是 MT5 **不做鼠标命中测试**：
悬停光标不变、点也点不中、`CHARTEVENT_OBJECT_DRAG` 根本不触发 —— 用户侧看到的就是
"**加出来的工具怎么拖都不动**"。

> 这与 MQL5 文档的字面读法有出入（文档只写"从对象列表中隐藏名字"），**是在本终端上实测出来的**：
> 移掉 `HIDDEN` 后立刻可拖。故可交互对象一律 `HIDDEN=false`。
> 同一次修复里还加了 `OBJPROP_SELECTED` 预选中做第二道保障，但**它救不了"命中不到"的对象**，
> 故**不是**本次的真正原因 —— 归因要写清楚，别把两道保险记成一笔功劳。
> 用户报告的关键症状是"**光标都不变**"：没有命中测试，就不可能靠"预选中"补救。

#### 已踩过的坑：宽度抓手抢不到鼠标命中（`v1.12-s1` 已修复）

**用户报告**：「盈亏比工具的宽度无法调整」（2026-09-30）。

**根因不是代码没写** —— `OnDragObj` 里 `_HL` / `_HR` 两个分支一直都在。问题在**画在哪**：
抓手是 `OBJ_ARROW(159)` 画在**入场线的两个端点**上，与 `OBJ_TREND` 的端点坐标**完全重合**，
于是 MT5 的鼠标命中判给了**线**：用户拖到的永远是入场线（工具被整体平移，宽度一动不动）。

**实证（不靠猜）**：这个指标的 `CHARTEVENT_OBJECT_DRAG` 处理里有一行**无条件打印**的日志
（`DBG … object-drag <对象名>`），于是终端日志本身就是取证工具。统计 2026-09-24 ~ 09-30 的全部日志：

| 对象 | 拖动事件次数 |
|---|---|
| `PT_1S_ENTRY` | 10 |
| `PT_1S_TP` | 10 |
| `PT_1S_SL` | 6 |
| **`_HL` / `_HR`（宽度抓手）** | **0** |

即：用户确实在拖，事件也确实送达了指标，但**从来没有一次落在抓手上**。这条零值就是根因的直接证据。

**修法（两条，互不依赖）**：
1. 抓手**挪到工具外侧**（`pH = 工具上沿 + 腿长×0.25`，离三根线都有距离），并从 `OBJ_ARROW` 换成
   `OBJ_TEXT` 的 **◆** 字形 —— `OBJ_TEXT` 的命中框是**文字外框**，比 8px 圆点大得多，字号还可调。
2. 面板上加一行 **`宽度 N 根` + `−N / +N` 两个按钮**：完全不依赖鼠标命中，是"无论如何都能改宽度"的兜底通道。

> ⚠️ 一般化的教训：**在 MT5 里，两个可选中对象的命中区域重叠时，判定权不归你**。
> 抓手、端点、标签这类"小对象"必须与线**拉开坐标距离**，否则它就是个画着好看的装饰。
> 与坑 ④（`HIDDEN=true` 命中不到）是**同一类问题的两种表现**：能看见 ≠ 能点到。

#### 拖不动的时候按这个顺序查

1. **先分清是"选不中"还是"拖了没反应"** —— 设 `InpDebug=true`，单击一根线，看专家日志：
   - 有 `DBG v1.10-s1 object-click <PT_1L_ENTRY>` ⇒ MT5 认得这个对象，问题在拖动环节
   - **没有**这一行 ⇒ MT5 根本没命中这个对象（回看上一节的 HIDDEN 坑），别再怀疑拖拽代码
2. 拖动后再看日志：必须有 `DBG v1.10-s1 object-drag <...>`。
   **这一行是无条件打印的**（不必开 `InpDebug`）—— "拖不动"发生时最需要它：
   **没有这一行 = 拖动事件根本没送到指标**，代码侧无从修起
3. **不依赖鼠标拖动的最后一条通路**：`Ctrl+B` 打开对象列表 → 找 `PT_1L_ENTRY` / `_SL` / `_TP`
   → 选中 → **方向键**微调（MT5 自带能力）。
   故本指标**不**设 `OBJPROP_HIDDEN=true`：那会让对象从列表里消失，等于把这条路一起堵死
4. 工具创建 / 被选中后，它的 5 个可拖对象会被**主动置为已选中**（`OBJPROP_SELECTED=true`）——
   因为"已选中"的对象在 MT5 里**不需要再点一次**就能按住拖动
5. ⚠️ 拖的是**线**和工具**外侧的 ◆ 抓手**，**不是绿 / 红色块**。色块画在背景层（`OBJPROP_BACK`）以免挡住 K 线，
   而 MT5 从设计上就不允许用鼠标选中背景对象 —— 要让它可拖只能牺牲"不挡 K 线"，故不做。
   ⚠️ 抓手**不能**放在线的端点上（会被线抢走命中），这是 `v1.12-s1` 实测出来的，见上一节坑 ④
6. 若你的终端在 **工具 → 选项 → 图表** 里存在「单击选中对象」一类开关，确保它是打开的。
   ⚠️ 如实标注：**本机这个终端版本没有对应的 MQL5 常量**（`CHART_SELECT_OBJECT_BY_SINGLE_CLICK`
   编译探针报 undeclared），**指标无法代设**，这一条**未能在我这边验证**
7. 同一张图上若挂着 `Structure` 等重绘型指标：已核实它们全部 `OBJPROP_SELECTABLE=false`
   且各自只删自己的前缀，**不会抢点击、不会误删**本指标的对象
